# Known traps

Pitfalls of the tested firmware (03.53.45, webOS 6.5.3) and its tools. `$TV_IP` is the address of your TV. The sections of [guide.md](guide.md) explain the setup around them.

- `luna-send` prints nothing over an SSH session without a terminal on the TV. Use `ssh -tt` for every `luna-send` check; the call works either way.
- `ares-install --device <root profile>` fails with `Error: Unable to exec` after the upload on this firmware. `scp` the IPK and use `luna://com.webos.appInstallService/dev/install`, as `scripts/install-root.sh` does.
- `ares-setup-device -i privatekey=<path>` breaks with an absolute path (it is resolved under `~/.ssh`). Use the key's name, for example `privatekey=lgtv_root_ed25519`.
- The TV drops SSH in standby while SSAP stays reachable. Wake it with an SSAP launch or the remote. Quick Start+ must be off.
- After installing Homebrew Channel, call `org.webosbrew.hbchannel.service/autostart` once (its UI or Luna) or nothing root-related runs at boot. Homebrew Channel appears in `listLaunchPoints` only after a reboot.
- The Developer Mode shell before root (`prisoner@$TV_IP:9922`) is chrooted and cannot run `luna-send`.
- Run `node scripts/build-catalog.mjs` only from the project folder; it writes `docs/all-apps.json` and `app/catalog.json`.
- Pi-hole v6 domain API: `PUT` and `DELETE /api/domains/{type}/{kind}/{domain}` take the domain text in the path, not the numeric id. An allow rule always wins over a deny rule, so check `/api/domains/allow` before you blame the deny list.
- On this firmware `iptables` has a `nat` table but no DNAT target (`No chain/target/match by that name`). Do not plan DNS-egress redirects without testing it.
- TV `/var/log` timestamps show 2021 until NTP syncs; the `init.d` hooks run before the clock is correct.
- The hidden-app list on webOS 6.5.3 is `/var/preferences/com.webos.applicationManager/blockedAppList/<REGION>.json` (`DEU.json` on the tested TV) with the key `blocked_applist`, not `blockedSystemAppList/<REGION>.json` and `blocked_system_applist`. The `webos-debloat` gist at its pinned revision hardcodes the latter and would hide nothing; the copy in `scripts/root/` has the two substitutions. The app manager reads the list only at start, so a reboot is needed. See [guide.md, step 3](guide.md#3-hide-apps-and-stop-preloading).
- `getForegroundAppInfo` shows only the card app. Settings (`com.palm.app.settings`) is an overlay: check it with `{"extraInfo":true}`, and note that launching it again while it is open closes it.
- A wrong TV clock (one hour behind after a reboot) breaks apps and the Content Store (error 102). It happened while `de.nextlgsdp.com` was blocked. After every reboot compare `date` on the TV with the Mac before you blame an app.
- The Content Store (error 102) needs `de.nextlgsdp.com`, `de.ibs.nextlgsdp.com`, `de.emp.lgsmartplatform.com`, `eic.tv.wiselg.com`, `de.lgrecommends.lgappstv.com`, `eic-ngfts.tv.wiselg.com`, `ngfts.tv.wiselg.com` and `eic-gfts.tv.wiselg.com` to resolve. The `de.` prefixes are the German region; your TV may use others. See [guide.md, step 2](guide.md#2-privacy).
- A DNS log does not show A queries for names that `/etc/hosts` maps to `0.0.0.0` (only the AAAA ones, as blocked). To find what an app needs: `umount /etc/hosts` for each hook mount (keep Homebrew Channel's, check `mount | grep hosts`), start the app, read the DNS log for your TV, intersect it with `scripts/root/blocklist.hosts`, then re-run `/var/lib/webosbrew/init.d/10-hosts-blocklist`. Each hook re-run stacks one more mount (harmless; a reboot resets it).
- The TV has no `jq` or `python`, only `node` (v8.12.0 in the shell). `/tmp` there is wiped by every reboot, so copy helper scripts again. If you have no SSH host entry for the TV, use `ssh -tt -i ~/.ssh/lgtv_root_ed25519 -o IdentitiesOnly=yes root@$TV_IP`.
- `luna-send -i .../appInstallService/dev/install` never exits after `"state":"installed"`; run it in the background on the TV and poll its log (see `scripts/install-root.sh`). A service started from an `ssh -tt` session dies when the session closes; start it from a plain `ssh` or the boot hook.
- A service id outside `com.webos.*` calls over the public bus; tvpowerd's `getPowerState` is private-bus only (`Unknown method`). Use `service.privateHandle`. bootd opens the app named in `physicalLastSourceAppId` of `/var/lib/eim/lastinput` at power-on; EIM rewrites that file at every input change.
- `com.webos.surfacemanager.disableHome` (set by the launcher service) survives a reboot. With the service and both hooks gone, HOME stays dead. The service sets it only after the launcher was seen in front. Emergency steps: [guide.md, step 4](guide.md#emergency-rollback-without-a-reboot).
- A hung `appInstallService` job is kept in `/var/palm/data/com.webos.appInstallService/installHistory2.db` and resumed at every boot; SAM keeps the app locked (`-102 app is locked`, installs answer "duplicate command"). Move that file aside and reboot. Before a reinstall, stop the service, close the app and start only one install at a time.
- After a cold start the system may connect the last TV input (Live TV tuner, `connectedSource` `VDEC`) to the MAIN video sink with no app in front, so its sound plays under the launcher. Closing apps does not free it; opening Live TV and then the launcher does (the "settle guard" in [CONTEXT.md](../CONTEXT.md)). Judge Live TV playback by `PlayAction ... Succeed` in `/var/log/broadcast.log`. With boot source `HDMI_1`, MAIN shows `connectedSource` `HDMI` and `contentType` `hdmi1` behind the launcher; that is not the tuner and the guard ignores it.
- A real mains cycle is a different boot path than `reboot` or the power key. With `general.homeAutoLaunch` `on`, bootd launches LG Home (`firstAppInHome`) and ignores `lastinput`. Only `remoteKey`, `localKey` and `upDownKey` power-ons use `{LAST_APP}`. The launcher setup needs `homeAutoLaunch` `off`.
- The stored preload list (`com.webos.service.preloadmanager.supportAppList`) is not the only source of the runtime policy. `airplay` is `isEnabled:false` there but `true` in `getPreloadPolicy` after every boot, and Netflix runs after some boots with `isEnabled:false`. Check `getPreloadPolicy` and SAM `running` after a reboot, not only the config.
- Live TV keeps decoding muted behind other apps (ADEC1 `play=1`, `frmCnt` rising in `/var/log/legacy-log`); the mute is lost at the wake from Active Standby. `closeByAppId com.webos.app.livetv` sets `play=0`; `preloadmanager` restarts Live TV hidden afterwards without restarting the decoder. The ADEC1 lines keep coming after the close, so check `play` and `frmCnt`, not the presence of lines.
- bootd calls `utp.boot/boot` at about 13.6 s with `deviceId` set to `physicalLastSourceId` of `/var/lib/eim/lastinput`. With `DTV` the tuner starts behind the app named there (Live TV picture and sound at a mains cycle). The service writes `HDMI_1` into that field next to the launcher app id. `need setChannel by utp` in `legacy-broadcast-booting.log` shows up for every boot; judge a tune by a `PlayAction` in `broadcast.log`.
- After a mains start the foreground launcher can be the `com.webos.app.inputcommon` stand-in: `getForegroundAppInfo {"extraInfo":true}` shows `windowGroup` `true` and the inputcommon pid (the real web launcher has `windowGroup` false and the `WebAppMgr` pid), the web app does not run and the screen is black. `getForegroundAppInfo {}` shows only `appId`, so a check that reads the foreground `appId` alone passes on a black screen. Judge every boot check by a screenshot (`com.webos.service.capture/executeOneShot`, then `scp` and open it); the call may answer `ERROR_INTERNAL` for a while after Live TV was in front.
- The hidden-app list was reset to LG's two entries at a boot on the tested TV (Disney+ back, 19 launch points); the cause is unproven (`sam` can rewrite it from a server answer, but the Store hosts must stay open). `removeLaunchPoint` refuses the system tiles (`removable: false`). What holds: `chattr +i` on the region file. `webos-debloat.sh --apply` fails while it is set, so `scripts/restore-custom-state.sh` runs `chattr -i` first. Hiding is cosmetic: only 5 of the 41 ids are tiles. The TV answers neither ping nor SSH in standby; a Wake-on-LAN packet to the TV's MAC address wakes it.
- `com.webos.service.capture/executeOneShot` also answers `ERROR_INTERNAL` while the screen saver is on (power state `Screen Saver`, about 2 min after power-on); `power/powerOn` refuses then (`-104`). A power off/on imitation ends it; take the screenshot within 2 min of `Active`.
- Do not run `grep -r` over `/var/log` or `/tmp` on the TV: it hung for minutes (load average above 30 after boot).
- A hidden app (in the region file) cannot be launched: `applicationManager/launch` answers `-101 not exist`, also for the system. The INPUT key launches `com.webos.app.homeconnect` (`inputHubAction` in `/usr/lib/qt5/qml/KeyFilters/appLaunch.js`; `com.webos.app.quickinputpicker` is not installed), so hiding the Home Dashboard kills the INPUT key. Un-hiding takes effect only after a reboot.
- Now and then an HDMI input app comes to the front without joining the video output: `videooutput/getStatus` lists no client with its `appId` (a working input has one within about 1 s, `HDMI` with a picture or `JPEG` for "No signal"), and the screen is black with only the input banner. Seen twice with `hdmi3` after `hdmi2`; not reproducible on demand. `closeByAppId` and a new launch fix it; the service does that once, 3 s after a tile launch.
